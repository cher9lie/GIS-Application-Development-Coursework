# 作业 9：栅格地形分析

## 作业目标

本作业使用 ArcGIS Spatial Analyst / GeoAnalyst 接口完成基础栅格读取和地形分析，练习栅格图层、像元索引、表面分析与属性提取。

## 环境与入口

- Visual Studio 2010
- .NET Framework 4.0
- ArcGIS Engine / Desktop 10.2
- 目标平台：x86
- Spatial Analyst 扩展许可
- 解决方案：`RasterAnalysisSystem.sln`
- 主要代码：`RasterAnalysisSystem/Form1.cs`
- 示例数据：`RasterAnalysisSystem/Data/dem.tif`

项目会把 `Data/*.*` 复制到输出目录。打开栅格对话框时，如果输出目录中存在 `Data`，程序会把它作为初始目录。

## 已实现功能

- 加载 TIF、IMG、JPG 栅格
- 计算坡度
- 计算坡向
- 按波段、行、列查询像元值
- 按指定等值距生成等值线
- 提取像元值大于指定阈值的区域
- 把分析结果添加到地图和 TOC

程序优先使用 TOC 当前选中的栅格；如果没有选中栅格，会从地图图层中寻找第一个栅格。

## 首次运行

1. 确认 ArcGIS Administrator 中 Spatial Analyst 可用。
2. 打开解决方案并选择 x86。
3. 生成、启动程序。
4. 点击“加载栅格数据”。
5. 选择随项目附带的 `Data/dem.tif`，或选择自己的单波段/多波段栅格。
6. 在 TOC 中选中要分析的栅格图层。
7. 再执行坡度、坡向、查询、等值线或提取。

若扩展许可无法签出，程序会显示警告；依赖 Spatial Analyst 的功能可能随后失败。

## 坡度计算

点击“坡度计算”后，程序用 `ISurfaceOp.Slope` 生成以“度”为单位的坡度栅格，Z 因子使用当前实现的默认值。结果作为名为“坡度图”的图层加入地图顶部。

如果水平坐标单位和高程单位不一致，应根据实际数据设置合适的 Z 因子；当前界面没有提供 Z 因子输入项。

## 坡向计算

点击“坡向计算”后，程序调用 `ISurfaceOp.Aspect`。结果作为“坡向图”加入地图。坡向值的含义遵循 ArcGIS 10.2 的 Aspect 工具约定。

## 灰度值/像元值查询

界面输入三个整数：

- 波段：索引从 0 开始
- 行：像元行号
- 列：像元列号

点击“灰度值查询”后，实际调用顺序为 `GetPixelValue(波段, 列, 行)`。行列超出范围、波段不存在或输入不是整数时会提示错误。该功能不是在地图上点选位置查询。

## 等值线

1. 在等值线输入框填写正数，默认值为 100。
2. 点击“生成等值线”。
3. 程序以 0 为基准值调用 `Contour`。
4. 结果作为要素图层添加到地图。

等值距必须大于 0。合理数值取决于 DEM 的高程范围和单位。

## 栅格提取

1. 在“高程 >”输入框填写阈值。
2. 点击“提取栅格”。
3. 程序构造 `Value > 阈值` 条件。
4. 用 `IExtractionOp.Attribute` 生成结果。
5. 结果按“提取_大于阈值”命名并加入地图。

输入支持当前区域格式和英文小数点格式，写入查询表达式时统一使用不受区域设置影响的格式。

## 结果保存说明

当前分析接口产生的结果主要作为临时/内存数据集加入地图，没有提供“另存为永久栅格”的界面。需要长期保留时，可在 ArcMap 中导出结果，或扩展代码为分析环境指定输出工作空间。

仓库删除了原 `bin/Debug` 中大量旧分析结果和编译产物；它们不是运行所需源码。随工程保留的 `dem.tif` 才是可重复使用的输入示例。

## 文档校正

原报告提到独立统计面板和自定义拉伸渲染器，但当前源码只是在部分流程中尝试读取栅格统计信息，没有实现可操作的统计面板，也没有显式创建拉伸渲染器，因此 README 不把它们列为功能。

## 常见问题

- “Spatial Analyst 许可开启失败”：检查扩展授权和许可级别。
- “未找到任何栅格图层”：先加载栅格，或在 TOC 中选中栅格。
- 结果图层创建失败：可能是返回对象类型、许可或临时工作空间问题。
- 坡度数值异常：核对水平坐标单位、高程单位和空间参考。
- 像元查询越界：确认影像宽高、波段数量以及索引从 0 开始。

## 已知限制

没有重采样、NoData 参数、环境范围、像元大小、输出坐标系和永久输出路径的界面配置。它是教学用最小实现，不应直接作为批量生产工具。
